# PROB-04: Landmark 9 Canonical Coordinate Drift in Multi-Signer Dataset

## 1. Problem Description
Synthetic multi-signer data generated by `scripts/generate_multisigner_dataset.py` exhibits subtle coordinate misalignment with live MediaPipe runtime canonical normalization, leading to reduced generalization on held signs.

## 2. Root Cause Analysis
In `backend/app/kinetics/geometry.py`:
Canonical alignment normalizes each hand by rotating it in 3D so that the wrist-to-middle-MCP vector ($\vec{v} = L_9 - L_0$) points strictly along the negative Y-axis:
$$L_9^{\text{live}} = (0.0, -1.0, 0.0)$$
In `scripts/generate_multisigner_dataset.py`:
During synthetic multi-signer augmentation, random 3D rotations were applied *after* initial normalization without re-enforcing the canonical constraint.
Diagnostics showed:
$$\text{mean}(L_9^{\text{synthetic}}) = (0.021, -0.912, 0.043), \quad \text{std} = 0.418$$
This discrepancy meant synthetic training examples deviated significantly from the strict $(0, -1, 0)$ orientation produced deterministically during live camera processing.

## 3. Implementation Plan & Proposed Fix
1. In `scripts/generate_multisigner_dataset.py`:
   - Enforce canonical projection *after* applying anthropometric scaling and physiological variations.
   - Constrain any simulated hand tilt to within $\pm 5^\circ$ planar wobble, and always re-center Landmark 0 at $(0,0,0)$ and re-align Landmark 9 to $(0, -1, 0)$.

## 4. Acceptance Criteria & Verification
- [ ] Synthetic dataset Landmark 9 has $\text{std} < 0.01$ along $X$ and $Z$ axes.
- [ ] Synthetic and live canonical vectors match within $1e-4$ precision.
