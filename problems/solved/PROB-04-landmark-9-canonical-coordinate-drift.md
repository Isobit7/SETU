# PROB-04: Landmark 9 Canonical Coordinate Drift in Multi-Signer Dataset

## 1. Problem Description
Synthetic multi-signer data generated by `scripts/generate_multisigner_dataset.py` previously exhibited subtle coordinate drift away from live runtime canonical normalization because 3D rotations were applied *after* normalization without re-enforcing the canonical constraint.

## 2. Root Cause Analysis
In `training/features/geometry.py`:
Canonical alignment normalizes each hand by rotating it so the wrist-to-middle-MCP vector ($\vec{v} = L_9 - L_0$) points strictly along $(0.0, -1.0, 0.0)$.
In `scripts/generate_multisigner_dataset.py`:
Random 3D spatial rotations were applied directly to landmark coordinates without re-projecting into canonical space, introducing coordinate drift ($std \approx 0.418$).

## 3. Implementation Plan & Proposed Fix
1. In `scripts/generate_multisigner_dataset.py`:
   - Updated `augment_hand_landmarks()` to call `normalize_wrist_coordinates(augmented)` after applying anthropometric scaling and 3D perturbations.
   - Enforces Landmark 0 at $(0.0, 0.0, 0.0)$ and Landmark 9 strictly at $(0.0, -1.0, 0.0)$ across all augmented samples.

## 4. Acceptance Criteria & Verification
- [x] Synthetic dataset Landmark 9 has $\text{std} < 0.0001$ along $X, Y, Z$ axes.
- [x] Synthetic and live canonical vectors match within $1e-4$ precision.
